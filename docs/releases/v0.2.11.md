# v0.2.11 – Leads Pipeline

## Purpose
Track prospects through a pipeline before they become real customers, with a clean path to "promote" a Won lead into your live Customers/Projects — built quickly given a new team member starting the next day, but without skipping the design decisions that would be expensive to redo.

## Changes
- New "Leads" nav section, first item in the sidebar.
- New `leads` collection — deliberately separate from `customers`/`projects`, so unconverted prospects never inflate your real customer/project counts.
- Pipeline: **Cold → Warm → Hot → Won/Lost**, plus a projected income figure per lead.
- Each lead links to either an **existing** Customer/Project (picked from your live data) or describes a **new (prospective)** one by name. Choosing "new customer" automatically forces and locks the project side to "new" too, since a not-yet-real customer can't already have a real project.
- **Promote to Customer/Project**: only enabled once a lead is Won, and only once per lead. Creates real records for whichever side (customer and/or project) was prospective; if the lead already pointed at real, existing records, promotion just links to them without creating duplicates. The lead itself stays on record afterward, marked as converted — it's not deleted.
- Edit locks the Customer/Project association (same reasoning as Projects/Bookings elsewhere) — only name, status, projected income and notes can change.
- Delete is a genuine permanent delete. Safe as a hard delete because nothing else references a lead, and deleting one never touches any Customer/Project already promoted from it.

## Firebase changes — action required
**Publish an updated `docs/firestore.rules.txt`** — it now includes a `leads` collection rule (admin-only, same pattern as `projects`). Nothing else changed; existing rules for other collections are untouched.

## Testing
1. Publish the updated Firestore rules.
2. Create a lead linking to an **existing** customer, with a **new (prospective)** project. Confirm it saves and shows correctly in the table and detail panel.
3. Create a second lead with a **new (prospective)** customer, and confirm the project side auto-locks to "new".
4. Try to Promote a Cold/Hot lead — confirm the button is disabled until status is Won.
5. Change a lead's status to Won (via Edit), then Promote it. Confirm real Customer and/or Project records appear in their respective pages, and the lead's detail panel now shows "Promoted: Yes".
6. Try Promoting the same lead again and confirm it's blocked with a clear message.
7. Delete a lead (not yet promoted) and confirm it's removed with no effect on Customers/Projects.
